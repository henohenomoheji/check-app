# 関連ナレッジ判定アプリケーション 要件・機能設計書

## 1. 目的・利用者

社内の複数の部署が、概要テキストや入力資料をもとに、事前登録済みナレッジから関連資料を判定する。テーマの一致や類似事例を確認し、関連理由と根拠を参照できるようにする。

| 項目 | 要件 |
|---|---|
| 利用者 | 社内の複数の部署 |
| 利用シナリオ | 事前登録済みナレッジから、入力内容に関連する資料を判定する |
| ナレッジ登録者 | システム管理者側 |
| ナレッジ参照範囲 | 利用者ごとに分けず、共通のナレッジを参照する |

ナレッジの参照範囲が共通であることと、利用者の入力資料・会話履歴を共有することは別の要件とする。入力資料・会話履歴の公開範囲は未決定。

## 2. 初期リリースの範囲

### 2.1 対象機能

| ID | 機能 | 目的・内容 | 決定状況 |
|---|---|---|---|
| F001 | 概要テキスト入力 | 判定したい内容をテキストで入力する | 確定 |
| F002 | ファイルアップロード・解析 | 入力資料から判定・質問に使用する内容を抽出する | 対象。形式・上限等は未決定 |
| F003 | 関連ナレッジ判定 | テーマ・類似事例をもとに関連資料を判定する | 確定。詳細基準は未決定 |
| F004 | 判定結果表示 | 資料名、関連理由、根拠の引用、ページ番号、原本へのリンクを表示する | 確定 |
| F006 | 追加質問・回答 | 判定結果、入力資料、ナレッジ全体について質問する | 確定 |
| F007 | 会話履歴の保存・一覧・再開 | 過去の会話を左サイドバーから開き、追加質問する | 既存設計の対象。詳細仕様は未決定 |

### 2.2 対象外

- アプリケーション内のナレッジ管理機能（登録・更新・削除の管理画面など）。
- 判定結果のエクスポート機能（PDF・Excel・CSVなどへの出力）。

システム管理者側による事前登録は必要だが、その登録・更新手段は別途決定する。

## 3. 基本利用フロー

1. 利用者が概要テキスト、ファイル、または両方を入力する。
2. ファイルがある場合、文書解析を行う。
3. 入力内容と事前登録済みナレッジをもとに、関連資料を判定する。
4. 判定結果と関連理由・根拠を表示する。
5. 利用者は判定結果を確認し、必要に応じて追加質問する。
6. 保存済みの会話を再開する場合は、履歴から選択して追加質問する。保存・再開の詳細は未決定。

## 4. 機能要件・業務ルール

### 4.1 入力（F001・F002）

| 入力パターン | 許可 |
|---|---|
| 概要テキストのみ | 可 |
| ファイルのみ | 可 |
| 概要テキストとファイルの両方 | 可 |
| どちらもなし | 不可 |

- 概要テキストまたはファイルのどちらか一方を必須とする。
- テキストの空文字・空白のみは未入力として扱う。
- 両方未入力の場合、入力を促すエラーを表示し、判定を開始しない。
- ファイルの対応形式、サイズ、数、ページ数およびテキスト文字数の上限は未決定。
- 解析失敗や抽出内容が空の場合の扱いは未決定。

### 4.2 既存ナレッジ

- システム管理者側が事前に登録したナレッジを判定・追加質問の対象とする。
- 利用者や部署によってナレッジの参照範囲を分けない。
- 対象資料の種類・件数、登録・更新方法、更新頻度、版管理は未決定。

### 4.3 関連ナレッジ判定（F003）

関連性は以下の観点で判断する。

| 観点 | 判断内容 |
|---|---|
| テーマ | 入力内容とナレッジの主題・扱う課題に関連があるか |
| 類似事例 | 入力内容と類似する事例がナレッジに含まれるか |

- 概要テキストと、ファイルがある場合はその解析内容を判定入力とする。
- 観点の優先順位、関連ありとする条件、表示件数、並び順、関連度の表示有無は未決定。
- 関連資料がない場合の表示方法は未決定。処理失敗とは区別する必要がある。

### 4.4 判定結果表示（F004）

関連資料ごとに以下を表示する。

| 項目 | 内容 |
|---|---|
| 資料名 | 関連すると判定されたナレッジの名称 |
| 関連理由 | テーマ・類似事例の観点で関連する理由 |
| 根拠の引用 | 判定根拠となる原文の抜粋 |
| ページ番号 | 引用箇所のページ番号 |
| 原本へのリンク | 対象ナレッジの原本を参照するリンク |

- 引用は対象資料の原文に対応し、ページ番号は引用箇所に対応すること。
- ページ番号を持たない資料や、根拠位置を取得できない場合の表示方法は未決定。
- 原本をブラウザーで閲覧するか、ダウンロードするかは未決定。

### 4.5 追加質問・回答（F006）

- 判定結果に加え、入力資料や登録済みナレッジ全体について質問できる。
- 質問対象を、関連すると判定されたナレッジだけに限定しない。
- 質問時の資料追加可否、判定前の質問可否、過去の会話を引き継ぐ範囲は未決定。
- 回答への根拠・引用の表示要件、資料に根拠がない場合の回答方法は未決定。

### 4.6 会話履歴・再判定・削除（F007）

既存設計では会話履歴の保存・一覧・再開を対象としている。以下は要件確定が必要。

- 履歴の保存対象、タイトル、並び順、保存期間。
- 再開時に引き継ぐ入力資料・判定結果・会話の範囲。
- 同一会話内の再判定、概要変更、資料追加・削除の可否。
- 再判定時に過去の結果を残すか、更新後のナレッジを使うか。
- 会話削除時の入力原本・解析結果・判定結果の削除範囲。

## 5. 受け入れ条件

以下は確定要件に基づく受け入れ条件案。未決定事項を確定した後に詳細化する。

| ID | 条件 | 期待する動作 |
|---|---|---|
| AC001 | 有効な概要テキストのみを入力 | ファイルなしで判定を実行できる |
| AC002 | 対応するファイルのみを入力し、解析に成功 | 概要テキストなしで判定を実行できる |
| AC003 | 概要テキストと対応するファイルを入力し、解析に成功 | 両方を判定入力として使用する |
| AC004 | テキスト未入力（空白のみを含む）かつファイルなし | エラーを表示し、判定を開始しない |
| AC005 | テーマ・類似事例に基づき関連資料が判定される | 資料名、関連理由、引用、ページ番号、原本リンクを表示する。ページ番号のない資料の扱いは別途確定する |
| AC006 | 根拠の引用とページ番号を表示 | 引用内容が原文と一致し、ページ番号が該当箇所に対応する |
| AC007 | 異なる部署の利用者がナレッジを参照 | 利用者・部署によるナレッジ参照範囲の制限を行わない |
| AC009 | 入力資料または判定結果に含まれない登録済みナレッジについて追加質問 | 質問対象として扱い、回答を生成できる。回答品質の判定条件は別途確定する |

解析失敗、判定失敗、関連資料なし、根拠なし、権限エラーなどの異常系・境界条件は、動作方針の確定後に追記する。

## 6. 未決定事項

| 優先度 | 項目 | 決める内容 |
|---|---|---|
| 高 | 入力上限 | ファイル形式・サイズ・数・ページ数、テキスト文字数 |
| 高 | ナレッジの範囲・運用 | 種類・件数、登録・更新方法、版管理 |
| 高 | 判定ルール | テーマ・類似事例の優先順位、関連ありの条件、件数・並び順 |
| 高 | 追加質問 | 質問可能なタイミング、根拠の表示、根拠がない場合の対応 |
| 高 | 認証・公開範囲 | ログイン方式、入力資料・会話履歴を本人のみ／部署内／全社のどこまで公開するか |
| 中 | 履歴・再判定 | 保存・再開、資料変更、旧結果保持、参照するナレッジの版 |
| 中 | エラー対応 | 一部資料の解析失敗時に継続するか、再試行方法、該当なし表示 |
| 中 | 原本・根拠表示 | 原本の閲覧方法、ページ番号のない資料の扱い |
| 中 | 保存・削除 | 保存期間、削除対象、削除権限 |
| 中 | 品質・性能 | 評価事例、精度の目標、許容待ち時間、想定利用者数・同時実行数 |

## 7. 後続設計への反映事項

- DB設計：根拠のページ番号、原本リンクの生成に必要な情報、資料・履歴の所有権、ナレッジの版管理を要件確定に合わせて見直す。
- 画面設計：3種類の入力パターン、判定根拠、ナレッジ全体への追加質問を反映する。
- AI処理設計：テーマ・類似事例の評価基準と、登録済みナレッジ全体を質問対象にする処理を具体化する。
- API・非機能設計：入力上限、認証、保存期間、性能目標の確定内容を反映する。
